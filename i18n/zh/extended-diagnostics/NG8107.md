# 对不可为空的值使用可选链

此诊断（Diagnostic）用于检测 Angular 模板（Template）中可选链（optional chaining）运算（`.?`）左侧的类型不包含 `null` 或 `undefined` 的情况。

```ts
import {Component} from '@angular/core';

@Component({
  // 安全地输出用户名，即使 `user` 是 `null` 或 `undefined` 也没问题。
  template: `<div>User name: {{ user?.name }}</div>`,
})
class MyComponent {
  // `user` 被声明为一个_不可能_是 `null` 或 `undefined` 的对象。
  user: {name: string} = {name: 'Angelino'};
}
```

## 这有什么问题？

对不可为空的输入使用可选链运算符不会产生任何效果，这说明值所允许的类型与它在模板中的呈现方式之间存在不一致。
开发者可能会合理地认为可选链运算符的结果可能是 `null` 或 `undefined`，但实际上它永远不会是这两个值中的任何一个。
这可能会让人对程序的预期输出产生困惑。

## 应该怎么做？

让模板与声明的类型保持一致。
仔细检查输入的类型，确认它是否真的应该可为空。

如果输入应该可为空，就在它的类型中加上 `null` 或 `undefined` 来表明这一点。

```ts
import {Component} from '@angular/core';

@Component({
  // 如果 `user` 为空值，就不会对 `name` 求值，表达式会
  // 返回该空值（`null` 或 `undefined`）。
  template: `<div>{{ user?.name }}</div>`,
})
class MyComponent {
  user: {name: string} | null = {name: 'Angelino'};
}
```

如果输入不应该可为空，就删除 `?` 运算符。

```ts
import {Component} from '@angular/core';

@Component({
  // 模板始终显示 `name`，因为 `user` 保证永远不会是 `null`
  // 或 `undefined`。
  template: `<div>{{ user.name }}</div>`,
})
class MyComponent {
  user: {name: string} = {name: 'Angelino'};
}
```

## 配置要求

必须启用 [`strictTemplates`](/tools/cli/template-typecheck#strict-mode)，扩展诊断（Extended Diagnostics）才会输出。
还必须启用 [`strictNullChecks`](/tools/cli/template-typecheck#strict-null-checks)，才会输出 `optionalChainNotNullable` 诊断。

## 如果无法避免怎么办？

可以通过编辑项目的 `tsconfig.json` 文件来禁用此诊断：

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "optionalChainNotNullable": "suppress"
      }
    }
  }
}
```

更多信息，请参阅[扩展诊断配置](/extended-diagnostics#configuration)。
