# 检测到循环依赖

Angular 检测到组件（Component）、指令（Directive）或管道（Pipe）之间存在循环依赖。当组件 A 导入组件 B，而组件 B 又（直接或间接地）导入组件 A，形成一个循环时，就会出现此错误。

这种循环引用会导致 Angular 无法正确初始化这些组件，从而产生类似下面的错误：

```text
NG0919: Cannot read @Component metadata. This can indicate a runtime circular dependency in your app that needs to be resolved.
```

在较旧的 Angular 版本中，你可能会看到类似下面的错误：

```text
Cannot read properties of undefined (reading 'ɵcmp')
```

## 常见原因

### 组件相互导入

最常见的原因是两个组件相互导入：

```ts [parent.ts]
import {Component} from '@angular/core';
import {Child} from './child';

@Component({
  selector: 'app-parent',
  imports: [Child],
  template: '<app-child/>',
})
export class Parent {}
```

```ts [child.ts]
import {Component} from '@angular/core';
import {Parent} from './parent';

@Component({
  selector: 'app-child',
  imports: [Parent],
  template: '<app-parent/>',
})
export class Child {}
```

### 间接循环引用

循环依赖也可能经由中间文件产生：

```text
ComponentA -> ComponentB -> ComponentC -> ComponentA
```

## 解决此错误

### 重构共享逻辑

把共享的功能移到一个单独的文件中，该文件不导入任何一个组件：

```ts [shared.service.ts]
import {Service} from '@angular/core';

@Service()
export class SharedService {
  // 共享逻辑写在这里
}
```

### 使用仅类型导入

如果你只需要 TypeScript 的类型，请使用 `import type`：

```ts
import type {Parent} from './parent';
```

仅类型导入会在编译时被擦除，不会造成运行时的循环依赖。

### 调整组件层级结构

思考一下这个循环依赖是否意味着存在设计问题。通常，最简洁的解决方案是把共享功能提取到第三个组件或服务（Service）中。

### 调试复杂的循环依赖

对于包含大量模块的复杂应用，手动找出循环依赖可能很困难。可以考虑使用 [madge](https://www.npmjs.com/package/madge) 之类的工具来可视化并检测循环导入：

```bash
# 安装 madge
npm install -g madge

# 检查循环依赖
madge --circular --extensions ts ./src

# 生成可视化图
madge --circular --extensions ts --image graph.svg ./src
```

这些工具可以帮助你找出整个项目中的循环依赖链，并生成可视化的依赖关系图。
