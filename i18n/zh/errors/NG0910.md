# 元素上存在不安全的绑定

当 Angular 检测到对某个安全敏感属性使用了属性绑定（Property Binding）或 attribute 绑定时，你就会看到这个错误。
Angular 要求这些属性以静态属性的形式设置，这样它们的值会在元素创建时设定，
并在元素的整个生命周期内保持不变。错误消息中会指明该属性和对应的元素。

这适用于：

- 用于建立 `<iframe>` 安全模型的属性：`sandbox`、`allow`、`allowFullscreen`、`referrerPolicy`、`csp`、
  `fetchPriority` 和 `credentialless`。它们必须在 `src` 或 `srcdoc` 属性之前应用。
- 可能改变另一个元素 `href` 的 SVG 动画属性，例如 `<animate>` 和 `<set>` 上的 `attributeName`。

例如，使用属性绑定时会抛出该错误：

```html
<iframe [sandbox]="'allow-scripts'" src="..."></iframe>
```

或者使用 attribute 绑定时：

```html
<iframe [attr.sandbox]="'allow-scripts'" src="..."></iframe>
```

此外，在指令（Directive）的宿主绑定（Host Binding）中使用类似模式时，也会抛出该错误：

```ts
@Directive({
  selector: 'iframe',
  host: {
    '[sandbox]': `'allow-scripts'`,
    '[attr.sandbox]': `'allow-scripts'`,
  },
})
class IframeDirective {}
```

## 调试该错误

错误消息中包含了组件的名称，带有不安全绑定的元素
就位于该组件的模板中。

推荐的解决方法是把上述属性作为静态属性使用，例如：

```html
<iframe sandbox="allow-scripts" src="..."></iframe>
```

如果你需要根据不同条件为这些属性设置不同的值，
可以使用 `@if` 或 `@switch` 控制流块来有条件地渲染合适的 `<iframe>` 元素：

```html
@if (someConditionA) {
  <iframe sandbox="allow-scripts" src="..."></iframe>
} @else if (someConditionB) {
  <iframe sandbox="allow-forms" src="..."></iframe>
} @else {
  <iframe sandbox="allow-popups" src="..."></iframe>
}
```
