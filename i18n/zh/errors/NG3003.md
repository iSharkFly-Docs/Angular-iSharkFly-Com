# 检测到导入循环

当前组件引用的某个组件、指令或管道，会要求编译器添加一条导入语句，而这条导入会形成导入循环。
例如，考虑这样一个场景：`Parent` 在其模板中引用了 `Child`：

```ts [parent.ts]
import {Component} from '@angular/core';
import {Child} from './child';

@Component({
  selector: 'app-parent',
  imports: [Child],
  template: '<app-child/>',
})
export class Parent {}
```

```ts [child.ts]
import {Component, inject} from '@angular/core';
import {Parent} from './parent';

@Component({
  selector: 'app-child',
  template: 'The child!',
})
export class Child {
  private parent = inject(Parent);
}
```

由于 `Child` 在其构造函数中引用了 `Parent`，因此已经存在一条从 `child.ts` 到 `parent.ts` 的导入。
::: tip 提示
父组件的模板中包含 `<child></child>`。
因此，为该模板生成的代码必须包含对 `Child` 类的引用。
为了建立这个引用，编译器必须添加一条从 `parent.ts` 到 `child.ts` 的导入，这会导致导入循环：

:::

```text

parent.ts -> child.ts -> parent.ts

```

## 远程作用域

如果你使用的是 NgModule，为了避免添加会产生循环的导入，编译器会在声明该组件的 `NgModule` 类中添加额外的代码来连接这些依赖。

这被称为「远程作用域（remote scoping）」。

## 库

遗憾的是，「远程作用域」代码具有副作用——这会阻碍摇树优化（tree shaking）——因此不能在库中使用。
所以在使用 `"compilationMode": "partial"` 设置构建库时，任何需要循环导入的组件都会引发 `NG3003` 编译器错误。

## 调试该错误

将要生成的循环会作为错误消息的一部分显示出来。
例如：

```text

The component Child is used in the template but importing it would create a cycle:
/parent.ts -> /child.ts -> /parent.ts

```

利用这些信息，找出被引用的组件、管道或指令是如何反过来依赖正在编译的组件的。
下面是一些解决问题的思路：

- 尝试重新组织依赖关系以避免循环。
  例如，使用一个存放在独立文件中的中间接口，两个相互依赖的文件都可以导入它，而不会造成导入循环。
- 把相互引用的类移到同一个文件中，从而避免它们之间的任何导入。
- 如果导入的声明只被用作类型，就把导入语句改为仅类型导入（使用 `import type` 语法），因为仅类型导入不会形成循环。
