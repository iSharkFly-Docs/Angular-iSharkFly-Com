# 未找到插入参考节点

Angular 抛出此错误，是因为它试图在自己跟踪的另一个节点旁边插入一个 DOM 节点，但那个节点已经不在 Angular 预期的位置上了。

Angular 会跟踪它渲染的 DOM 节点，这样之后才知道在哪里插入、移动或移除内容，例如在 `@for` 块重新渲染时。如果 Angular 之外的某些东西修改了这部分 DOM（移除了某个节点，或把它移到了别处），Angular 的内部记录就会过时。下一次它尝试在该节点旁边插入内容时，你就会看到这个错误，而不是一个令人困惑的原生 `NotFoundError`。

导致这种情况的原因可能有：

- 应用代码直接操作 DOM（`ElementRef.nativeElement`、`document.querySelector`、`innerHTML` 等），而没有通过 Angular。
- 浏览器扩展修改了页面，例如翻译工具、语法检查器或密码管理器。
- Angular 自身在重新排序或条件渲染视图的代码（`@for`、`@if`、动态创建的视图）中存在边界情况。

下面的示例会触发此错误：

```ts
@Component({
  selector: 'app-example',
  template: `@if (show) {
    <span>{{ text }}</span>
  }`,
})
export class Example {
  show = true;
  text = 'hello';
  hostElement = inject(ElementRef).nativeElement;

  ngAfterViewInit() {
    // 绕过 Angular 移除这个节点，正是导致该错误的原因。
    this.hostElement.querySelector('span').remove();
  }
}
```

## 调试该错误

错误消息会告诉你 Angular 期望找到的是哪个节点，所以从那里开始排查。

- 在该组件（或其父组件）中查找直接操作 DOM 而没有使用 Angular API 的代码，并改用 Angular API。
- 如果错误只在部分用户那里出现，或者你在本地安装了某个扩展后可以复现，请尝试在关闭扩展的无痕窗口中测试。
- 如果在同一个路由上，许多不同用户都会稳定地遇到此错误，那么它很可能不是扩展造成的（扩展因用户而异）——请改为在该页面中寻找确定性的原因，例如以不寻常的方式重新排序或移除内容的 `@for`/`@if`，或者嵌入在该页面中的第三方小部件。
- 如果以上都无法解释，请提交一个附带复现示例的 issue。
