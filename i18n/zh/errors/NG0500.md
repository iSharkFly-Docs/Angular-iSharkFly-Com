# 水合节点不匹配

此错误表示在水合（Hydration）过程中，Angular 期望的 DOM 结构与服务端渲染期间所渲染并标注的结构一致。然而在客户端上，DOM 树与服务端渲染的 DOM 树并不相同。

此错误通常是由于使用浏览器原生 API 直接操作 DOM，在 Angular 生成的内容之外改变了 DOM 结构所致。如果你使用 `innerHTML` 或 `outerHTML` 设置 HTML 内容，也会出现此错误，因为它们同样会在 Angular 生成的内容之外改变 DOM 结构。要解决这个问题，可以重构组件（Component），改用 Angular 原生 API 而不是浏览器原生 API。如果无法做到，可以在组件的宿主节点上添加 `ngSkipHydration` 属性，这会禁用该组件及其子组件的水合。`ngSkipHydration` 只应作为最后手段使用，并应被视为一个需要修复的 bug。

有关水合的更多信息，请参阅[这篇指南](/guide/hydration)。

下面的示例会触发此错误。

```ts
@Component({
  selector: 'app-example',
  template: '<div><span>world</span></div>',
})
export class Example {
  hostElement = inject(ElementRef).nativeElement;

  ngOnInit() {
    // 创建一个新的 <p> 元素，其中包含 `Hello` 文本
    const newNode = document.createElement('p');
    newNode.innerHTML = 'Hello';

    // 把 <p> 插入到第一个元素之前。由于 Angular 并不知道这个 <p> 元素，
    // 它会在第一个元素的位置上查找 <div> 元素。结果就会抛出水合不匹配错误。
    // 正确的做法是更新组件模板，在模板中创建 <p> 元素。
    this.hostElement.insertBefore(newNode, this.hostElement.firstChild);
  }
}
```

## 调试此错误

开发者控制台中的错误消息会包含导致问题的应用 DOM 结构中具体部分的信息。检查应用的这一部分是否存在与水合相关的错误，例如使用原生 API 直接操作 DOM。

检查模板的 HTML 结构是否有效。更多信息请参阅[水合指南](/guide/hydration#valid-html-structure)。

作为一种可行的变通方案，你可以在组件宿主节点上添加 `ngSkipHydration` 属性。

如果应用在开发环境中正常运行，但在生产构建中出现水合错误，请确保发送给浏览器的 HTML 中包含 Angular 在服务端渲染期间生成的注释节点。Angular 运行时会把这些注释节点用作视图容器的锚点（无论是否启用水合），水合过程要求它们出现在原来的位置上。如果你有自定义逻辑会从服务端渲染生成的 HTML 中移除注释节点，或者你的 CDN 被配置为在返回内容前移除它们，请禁用注释节点的移除，然后检查水合错误是否消失。

## 常见原因

CDN 功能或浏览器扩展也可能在水合开始之前修改来自服务端的 HTML。这时你可能只在生产环境中、或只在部分用户那里看到此错误。请阅读水合指南中的 [CDN 与浏览器扩展](/guide/hydration#cdns-and-browser-extensions)。
