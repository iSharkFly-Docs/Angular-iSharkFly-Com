# 在响应式上下文中调用了不允许的函数

在响应式上下文中调用了一个不允许在响应式上下文中运行的函数。

例如，不能在 `computed` 或正在执行的副作用（Effect）中调度 `effect`。
避免在模板表达式中调用 `effect` 之类的函数，因为模板表达式会在它们自己的响应式上下文中执行。

计算表达式应当是纯的。
纯的意思是表达式不会触发任何副作用。
副作用是指调度 `afterNextRender`/`afterEveryRender`、创建新的 `effect` 或订阅 Observable 等操作。

为了避免常见的陷阱，有些操作在响应式上下文中被明确禁止。
例如，在 `computed` 中使用 `afterNextRender`/`afterEveryRender`，会在每次计算表达式求值时都调度新的渲染钩子。
这很可能不是你想要的，并且可能降低应用性能。

### 修复该错误

本错误指南并不详尽。
它只列出了几种常见场景以及如何处理该错误。

#### `afterNextRender`/`afterEveryRender`

把对 `afterNextRender`/`afterEveryRender` 的调用移到响应式上下文之外。

调度渲染后钩子的一个好位置是组件的类构造函数。
或者，使用 `untracked` 离开响应式上下文，显式地选择不触发此错误。

#### `effect`

把对 `effect` 的调用移到响应式上下文之外。

调度副作用的一个好位置是 `@Component` 的类构造函数。

#### `toSignal`

把对 `toSignal` 的调用移到响应式上下文之外。

```ts
result = computed(() => {
  const dataSignal = toSignal(dataObservable$);
  return doSomething(dataSignal());
});
```

可以重构为：

```ts
dataSignal = toSignal(dataObservable$);
result = computed(() => doSomething(dataSignal()));
```

或者，如果无法这样做，可以考虑手动订阅该 Observable。

作为最后的手段，可以使用 `untracked` 离开响应式上下文。
要小心，因为离开响应式上下文可能会导致 `untracked` 内部的信号读取被忽略。

### 调试该错误

错误消息会提到被意外调用的函数。
在你的应用代码中查找对该函数的调用。

另外，浏览器中的堆栈跟踪也会显示该函数在何处被调用以及它位于何处。
