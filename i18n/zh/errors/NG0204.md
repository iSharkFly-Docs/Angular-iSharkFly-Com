# 无效的注入令牌

当 Angular 在依赖注入（Dependency Injection）过程中无法为某个类解析依赖时，就会出现这个错误。它最常影响使用构造函数注入的类，因为在这种情况下 Angular 要依靠 TypeScript 元数据来确定参数类型。

最常见的原因有：

1. 服务（Service）类缺少 `@Service()` 或 `@Injectable` 装饰器
2. 某个 `InjectionToken` 缺少正确的提供者（Provider）定义
3. 某个构造函数参数无法解析

::: info 注意
`inject()` 函数接收的是显式的令牌，因此「参数无法解析」的情况并不直接适用于它。不过，如果被注入的类本身缺少 `@Service()`，并且它自己还有构造函数依赖，那么这个错误仍然可能出现。

:::

## 常见场景

### 缺少 `@Service()` 装饰器

当一个类有构造函数依赖却缺少 `@Service()` 装饰器时，Angular 无法解析它的参数：

```ts [Missing @Service() decorator]
export class UserClient {
  constructor(private http: HttpClient) {} // Angular 无法解析这个参数
}
```

添加 `@Service()` 装饰器即可修复：

```ts
@Service()
export class UserClient {
  constructor(private http: HttpClient) {}
}
```

### 无法解析的构造函数参数

当 Angular 无法确定某个构造函数参数的类型时，也会出现这个错误：

```ts
@Service()
export class DataStore {
  // 没有提供者，Angular 无法解析 'config'
  constructor(private config: AppConfig) {}
}
```

请确保所有构造函数参数要么已配置了提供者，要么对可选依赖使用 `@Optional()`。

## 调试该错误

错误消息中包含了哪个令牌无法解析的详细信息：

- `Can't resolve all parameters for X: (?, ?, ?)`——其中的 `?` 标记表示无法解析的参数。检查该类是否带有 `@Service` 或 `@Injectable()`，以及所有依赖是否都有提供者。
- `Token X is missing a ɵprov definition`——使用了某个 `InjectionToken` 却没有为其配置提供者。可以用 `{provide: TOKEN, useValue: ...}` 为该令牌注册一个值，或者在令牌定义中添加默认工厂。

从错误的堆栈跟踪倒推，找出出问题的注入发生在哪里，然后确认：

1. 该类带有 `@Service` 或 `@Injectable()` 装饰器
2. 所有构造函数参数都有已注册的提供者
3. 每个 `InjectionToken` 都配置了提供者或默认值
