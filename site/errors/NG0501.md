# 水合时缺少兄弟节点 {#hydration-missing-siblings}

此错误与[错误 NG0500](/errors/NG0500) 类似，但它表示 Angular 的水合（Hydration）过程在 DOM 的某个特定位置期望找到更多的兄弟节点，却没有找到。与直接操作 DOM 相关的原因，请查看[错误 NG0500](/errors/NG0500) 页面。

## 常见原因：服务端与客户端的条件内容不一致 {#a-common-cause-conditional-content-that-differs-between-server-and-client}

除了直接操作 DOM 之外，当 `@if` 或 `@for` 中的内容在服务端渲染的结果与客户端水合时不同时，也经常会出现此错误。如果服务端把某个条件渲染为 `true`（或渲染了一个包含更多项的列表），而客户端在水合时看到的却是 `false`（或一个更短的列表），那么客户端期望的兄弟节点就会比服务端实际发送的少。于是水合在遍历兄弟节点时失败。

一种常见的情况是：某个值来自 `input()`，但没有直接使用该输入（或通过 `computed()` 使用），而是在 `ngOnInit()` 或构造函数中一次性复制到一个普通的 `signal()` 里：

```ts
@Component({
  selector: 'app-example',
  template: `
    @if (visibleItems().length) {
      <ul>
        @for (item of visibleItems(); track item) {
          <li>{{ item }}</li>
        }
      </ul>
    }
  `,
})
export class Example {
  items = input<string[]>();

  // 这里只运行一次。如果在 `ngOnInit` 运行的那一刻
  // `items()` 还没有就绪，那么这个信号在服务端和客户端上
  // 可能会持有不同的值。这意味着两端渲染出的 DOM 节点
  // 数量不同，从而导致水合不匹配。
  visibleItems = signal<string[]>([]);

  ngOnInit() {
    this.visibleItems.set(this.items() ?? []);
  }
}
```

修复方法是派生这个值，而不是一次性复制它。这样每次渲染（包括第一次）都始终与输入保持一致：

```ts
export class Example {
  items = input<string[]>();

  visibleItems = computed(() => this.items() ?? []);
}
```

如果你还需要让用户在本地覆盖这个值，例如通过一个 "show more" 按钮显示更多项，请使用 [`linkedSignal()`](/guide/signals/linked-signal)，而不是在生命周期钩子中设置普通的 `signal()`。

## 调试该错误 {#debugging-the-error}

与直接操作 DOM 相关的调试技巧，请参见[错误 NG0500](/errors/NG0500)。

仅凭此错误无法知道是哪个组件导致的。[Angular DevTools 浏览器扩展](/tools/devtools)可以提供帮助：它能高亮显示发生水合不匹配的具体组件。找到该组件后，查看它是如何计算模板中 `@if` 或 `@for` 所用的值的。检查该值是直接来自 `input()`（通过模板绑定或 `computed()`），还是像上面那样在生命周期钩子中被复制到了某个信号里。
