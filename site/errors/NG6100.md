# 将 NgModule.id 设为 module.id 的反模式 {#ngmodule-id-set-to-module-id-anti-pattern}

把 `module.id` 用作 NgModule 的 `id` 是一种常见的反模式，在你的代码中很可能起不到任何有用的作用。

NgModule 可以声明一个 `id`：

```ts
@NgModule({
  id: 'my_module',
})
export class MyModule {}
```

声明 `id` 之后，就可以通过 `getNgModuleById()` 操作查找到该 NgModule。这项功能很少用到，主要用于某些非常特殊的打包场景，即在没有直接引用的情况下延迟加载（Lazy Loading）NgModule。在大多数 Angular 代码中，应当改用 ES 动态 `import()`（`import('./path/to/module')`），因为它能直接引用正在加载的 NgModule，而不需要全局注册这种副作用。

如果你没有使用 `getNgModuleById`，就不需要为 NgModule 提供 `id`。提供 `id` 有一个明显的缺点：它会使 NgModule 无法被摇树优化（tree-shaking），从而可能影响你的打包体积。

尤其是 `id: module.id` 这种写法，源于对 `@NgModule.id` 的误解。在早期版本的 Angular 中，有时需要在 `@Component` 元数据中加入 `moduleId: module.id` 属性。

## 调试该错误 {#debugging-the-error}

你可以从 NgModule 中移除 `id: module.id` 声明。编译器会忽略这个声明，并改为发出此警告。
