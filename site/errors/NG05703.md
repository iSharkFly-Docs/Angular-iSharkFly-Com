# SSR 期间出现可疑的 URL 源变更 {#suspicious-url-origin-change}

当服务端渲染（SSR）环境中某次 URL 解析导致了意外的源（origin）变更时，就会出现这个错误。这项检查是 `@angular/platform-server` 中的一项安全特性，用于保护你的应用免受服务端请求伪造（SSRF）和安全绕过攻击。

## 说明 {#description}

为了在 SSR 期间执行 HTTP 请求并处理路由状态，Angular 必须把相对 URL 解析为绝对 URL。

在解析过程中，Angular 会验证解析后的 URL 不会意外地指向外部或不受信任的源。如果某个 URL 表现得像相对路径，却被解析到了不同的源，Angular 就会抛出 `NG05703` 并阻止该请求或导航。

### 常见原因 {#common-causes}

- **以反斜杠开头的劫持尝试（开放重定向 / SSRF 绕过）：** 以斜杠和反斜杠开头的相对路径（例如 `/\\attacker.com/path` 或 `\\\\attacker.com/path`）可能会被浏览器和服务端 URL 解析器以不同方式解释。在某些解析器实现中，这些路径会被解析成指向 `attacker.com` 的绝对 URL。Angular 会检测到这种不一致并阻止解析。
- **不允许的跨源状态变更：** 当环境被配置为只允许在当前源内更改 URL 时，导航或 URL 更新（例如使用 `location.replaceState` 或 `location.pushState`）改变了应用的源。
- **SSR 引导 URL 不匹配：** 在服务端渲染中，如果传给渲染器的 `url` 与应用配置的基础源（例如 `APP_BASE_HREF`）不一致，路由器（Router）可能会在启动时尝试同步位置，从而导致不允许的源变更。
- **经过混淆的协议方案：** 带有混淆或格式错误协议的绝对 URL（例如 `ht\ntp://evil.com/path`）试图绕过源检查。

## 调试该错误 {#debugging-the-error}

检查触发错误的 URL。确保其中不包含意外的反斜杠、换行符或其他可能引发解析异常的字符：

- 避免在相对 URL 或路由路径中使用反斜杠（`\`）。
- 确保任何由用户提供的 URL 或查询参数在 SSR 中处理之前都经过了适当的验证和清理。
- **让 SSR 引导 URL 与配置的基础 URL 保持一致：** 如果错误发生在 SSR 环境的启动阶段，请确保传给渲染器的 `url` 与预期的基础源 / 主机（例如 `APP_BASE_HREF`）相匹配。如果原始请求头（例如 `X-Forwarded-Host`）中的动态 URL 与受信任的应用源不匹配，请避免使用它们。
- 如果你确实想通过协议相对 URL（`//other-domain.com/path`）向其他域名发起请求，请确保配置允许这样做，或者使用显式的协议（`http://` 或 `https://`）。
