# 注入器已被销毁 {#injector-has-already-been-destroyed}

当你试图从一个已被销毁的注入器（Injector）中获取服务时，就会出现这个错误。这通常发生在组件、指令或模块已被销毁之后，代码仍试图访问依赖的情况下。

## 常见场景 {#common-scenarios}

### 在销毁之后的回调中访问服务 {#accessing-services-in-callbacks-after-destruction}

组件被销毁时，它的注入器也会被销毁。如果之后某个异步回调试图访问服务，就会出现这个错误：

```ts
@Component(/* ... */)
export class UserProfile implements OnInit {
  private userClient = inject(UserClient);

  ngOnInit() {
    setTimeout(() => {
      // 错误：如果组件在定时器触发之前就被销毁了，
      // 注入器就已经不可用了
      this.userClient.fetchData();
    }, 5000);
  }
}
```

### 在取消订阅之后访问服务 {#accessing-services-after-unsubscribing}

如果清理工作的执行顺序不对，Observable 也会出现类似的问题：

```ts
@Component(/* ... */)
export class DataView implements OnDestroy {
  private dataStore = inject(DataStore);

  ngOnDestroy() {
    // 有问题：在其他清理工作可能已经完成之后，
    // 仍在销毁过程中尝试使用注入器
    this.dataStore.cleanup();
  }
}
```

## 调试该错误 {#debugging-the-error}

要修复这个错误：

1. **检查异步操作**——确保组件销毁时，回调、Promise 和订阅都已被取消。使用 `takeUntilDestroyed()` 或 `DestroyRef` 进行清理。

2. **尽早获取依赖**——把服务的引用保存在类字段中，而不是在回调里访问注入器。

3. **防范已销毁的状态**——对于可能比组件存活更久的操作，在访问服务之前先检查组件是否仍处于活动状态。

```ts
@Component(/* ... */)
export class UserProfile implements OnInit {
  private destroyRef = inject(DestroyRef);
  private userClient = inject(UserClient);

  ngOnInit() {
    // 使用 takeUntilDestroyed，在销毁时自动取消
    interval(5000)
      .pipe(takeUntilDestroyed(this.destroyRef))
      .subscribe(() => {
        this.userClient.fetchData();
      });
  }
}
```

堆栈跟踪会指出访问已销毁注入器的位置。从那里倒推，找出比其所属组件存活更久的异步操作。
