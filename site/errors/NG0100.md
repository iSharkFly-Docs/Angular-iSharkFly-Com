# 表达式在检查后发生了变化 {#expression-changed-after-checked}

<iframe src="https://www.youtube.com/embed/O47uUnJjbJc" title="Video" style="width:100%;aspect-ratio:16/9;border:0" allowfullscreen></iframe>

当某个表达式的值在变更检测（Change Detection）完成之后又发生了变化时，Angular 会抛出 `ExpressionChangedAfterItHasBeenCheckedError`。Angular 只会在开发模式下抛出此错误。

在开发模式下，Angular 会在每次变更检测运行之后执行一次额外的检查，以确保绑定没有发生变化。这可以捕获让视图处于不一致状态的错误。例如，当某个方法或 getter 每次调用都返回不同的值，或者子组件修改了其父组件上的值时，就可能出现这种情况。只要出现其中任何一种情况，就说明变更检测没有稳定下来。Angular 抛出此错误是为了确保数据始终能正确地反映在视图中，从而避免 UI 行为异常或可能出现的无限循环。

当你添加了模板表达式，或开始实现 `ngAfterViewInit`、`ngOnChanges` 等生命周期钩子（Lifecycle Hook）时，经常会出现此错误。在处理加载状态和异步操作，或者子组件修改了其父组件的绑定时，此错误也很常见。

## 调试该错误 {#debugging-the-error}

CLI 生成的[源码映射（source map）](https://developer.mozilla.org/docs/Tools/Debugger/How_to/Use_a_source_map)在调试时非常有用。沿着调用栈向上查找，直到找到错误中所显示的值发生变化的那个模板表达式。

确保在变更检测运行之后，模板中的绑定不会再发生变化。这通常意味着需要重构代码，为你的使用场景选用正确的组件生命周期钩子。如果问题出在 `ngAfterViewInit` 中，推荐的解决方案是使用构造函数或 `ngOnInit` 来设置初始值，或者使用 `ngAfterContentInit` 处理其他值的绑定。

如果你在视图中绑定了方法，请确保该方法的调用不会更新模板中的其他任何绑定。

关于哪种解决方案适合你，请阅读 ['Everything you need to know about the "ExpressionChangedAfterItHasBeenCheckedError" error'](https://medium.com/angular-in-depth/everything-you-need-to-know-about-the-expressionchangedafterithasbeencheckederror-error-e3fd9ce7dbb4)；关于这种检查为什么有用，请阅读 ['Angular Debugging "Expression has changed after it was checked": Simple Explanation (and Fix)'](https://blog.angular-university.io/angular-debugging)。
