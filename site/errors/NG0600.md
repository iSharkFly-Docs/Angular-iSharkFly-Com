# 在不允许的上下文中写入信号 {#signal-write-in-a-disallowed-context}

当在 `computed` 或模板求值期间写入信号（使用 `set` 或 `update`）时，Angular 会抛出此错误。这两者都应当只读取信号，在其中写入信号会在计算状态的过程中改变状态。

错误消息会说明属于哪一种情况。

## 不允许在 `computed` 中写入信号 {#writing-to-signals-is-not-allowed-in-a-computed}

`computed` 应当从其他信号派生出自己的值，且不产生副作用：

```ts
count = signal(1);
total = signal(0);

doubled = computed(() => {
  this.total.set(this.count() * 2); // 不允许
  return this.count() * 2;
});
```

如果该值只依赖于其他信号，就把它本身也定义成 `computed`，而不是把它存起来：

```ts
count = signal(1);
total = computed(() => this.count() * 2);
```

如果该值还需要可写，请使用 `linkedSignal`；如果写入是变化带来的副作用，请使用 `effect`。

在 `linkedSignal` 的计算过程中进行写入，也会抛出同样的错误。

## 不允许在 Angular 渲染模板时写入信号 {#writing-to-signals-is-not-allowed-while-angular-renders-the-template}

模板表达式在渲染期间运行，因此从模板中调用的方法也不能写入信号：

```ts
@Component({
  selector: 'app-example',
  template: '<p>{{ label() }}</p>',
})
export class Example {
  views = signal(0);

  label() {
    this.views.update((v) => v + 1); // 不允许
    return `Viewed ${this.views()} times`;
  }
}
```

把写入操作移到变化实际发生的地方。在事件监听器、生命周期钩子、输出处理函数和副作用中都允许写入信号。

## 使用 `untracked` {#using-untracked}

包裹在 `untracked` 中的写入不会抛出错误。只有当写入是有意为之且无法移走时才使用它，并且要记住，在 `untracked` 中读取的信号同样不会被跟踪。

## 调试该错误 {#debugging-the-error}

堆栈跟踪会指向 `set` 或 `update` 调用。从那里出发，找到调用它的 `computed`、`linkedSignal` 或模板表达式。
