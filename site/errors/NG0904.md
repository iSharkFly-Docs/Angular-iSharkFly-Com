# 在资源 URL 上下文中使用了不安全的值 {#unsafe-value-used-in-a-resource-url-context}

当模板或宿主绑定（Host Binding）把一个会加载外部资源的属性（例如 `<iframe src>` 或 `<link href>`）设置为一个未被显式标记为可信的值时，Angular 会抛出此错误，错误消息为 `unsafe value used in a resource URL context`。

资源 URL 与普通 URL 的处理方式不同。Angular 可以清理普通 URL，但无法让任意的资源 URL 变得安全，因为这些属性会让浏览器获取并执行外部内容。因此，Angular 会直接拒绝不可信的值，而不是尝试清理它们。

会触发此检查的属性如下：

| 元素       | 属性               |
| ---------- | ------------------ |
| `<base>`   | `href`             |
| `<embed>`  | `src`              |
| `<frame>`  | `src`              |
| `<iframe>` | `src`              |
| `<link>`   | `href`             |
| `<object>` | `codebase`, `data` |

## 调试此错误 {#debugging-the-error}

把任何普通字符串绑定到上述属性之一时都会抛出此错误，即使它看起来是一个静态 URL：

```ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="url"></iframe>`,
})
export class App {
  url = 'https://example.com/embed';
}
```

用 `SecurityContext.URL` 把值传给 `DomSanitizer.sanitize()` 也无济于事。`sanitize()` 返回的是普通字符串，而资源 URL 上下文永远不接受普通字符串：

```ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="sanitized"></iframe>`,
})
export class App {
  private readonly sanitizer = inject(DomSanitizer);
  sanitized = this.sanitizer.sanitize(SecurityContext.URL, 'https://example.com/embed'); // 仍然会抛出 NG0904
}
```

改用 `SecurityContext.RESOURCE_URL` 调用 `sanitize()` 同样会抛出错误，只不过是 [NG05201](/errors/NG05201)，因为 `sanitize()` 无法让任意字符串在资源 URL 上下文中变得安全。

如果 URL 来自可信、受控的来源，请使用 `DomSanitizer.bypassSecurityTrustResourceUrl` 将其标记为安全：

```ts
import {DomSanitizer, SafeResourceUrl} from '@angular/platform-browser';
import {Component, inject} from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<iframe [src]="safeUrl"></iframe>`,
})
export class App {
  safeUrl: SafeResourceUrl = inject(DomSanitizer).bypassSecurityTrustResourceUrl(
    'https://example.com/embed',
  );
}
```

::: danger 严重
`bypassSecurityTrustResourceUrl` 是一个逃生舱，而不是清理器。永远不要把用户提供的 URL 传给它，否则攻击者就能加载任意内容，包括恶意脚本。只有当值完全处于你的控制之下时才使用它。

:::

更多信息请参阅[安全指南](/best-practices/security#trusting-safe-values)。
