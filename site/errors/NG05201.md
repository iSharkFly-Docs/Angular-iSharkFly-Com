# 向 DomSanitizer 传入了不安全的资源 URL {#unsafe-resource-url-passed-to-domsanitizer}

当使用 `SecurityContext.RESOURCE_URL` 和一个未被显式标记为可信的值调用 `DomSanitizer.sanitize()` 时，Angular 会抛出此错误，错误消息为 `unsafe value used in a resource URL context`。

资源 URL 与普通 URL 的处理方式不同。Angular 可以清理普通 URL，但无法让任意的资源 URL 变得安全，因为资源 URL 属性（例如 `<iframe src>` 或 `<link href>`）会让浏览器获取并执行外部内容。因此，`sanitize()` 会直接拒绝不可信的值，而不是尝试清理它们。

如果在模板或宿主绑定（Host Binding）中把不可信的值绑定到这些属性之一，则会抛出 [NG0904](/errors/NG0904)。

## 调试此错误 {#debugging-the-error}

查找使用了 `SecurityContext.RESOURCE_URL` 的 `sanitize()` 调用。任何普通字符串都会导致此错误，即使它看起来是一个静态 URL：

```ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="url"></iframe>`,
})
export class App {
  private readonly sanitizer = inject(DomSanitizer);
  url = this.sanitizer.sanitize(SecurityContext.RESOURCE_URL, 'https://example.com/embed'); // 抛出 NG05201
}
```

如果 URL 来自可信、受控的来源，请使用 `DomSanitizer.bypassSecurityTrustResourceUrl` 将其标记为安全，并直接绑定结果：

```ts
import {DomSanitizer, SafeResourceUrl} from '@angular/platform-browser';
import {Component, inject} from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<iframe [src]="safeUrl"></iframe>`,
})
export class App {
  safeUrl: SafeResourceUrl = inject(DomSanitizer).bypassSecurityTrustResourceUrl(
    'https://example.com/embed',
  );
}
```

::: danger 严重
`bypassSecurityTrustResourceUrl` 是一个逃生舱，而不是清理器。永远不要把用户提供的 URL 传给它，否则攻击者就能加载任意内容，包括恶意脚本。只有当值完全处于你的控制之下时才使用它。

:::

更多信息请参阅[安全指南](/best-practices/security#trusting-safe-values)。
