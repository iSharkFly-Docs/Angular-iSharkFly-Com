# NgZone 始终处于不稳定状态 {#application-remains-unstable}

这个警告只会在浏览器中、客户端启用了水合（Hydration）的过程中出现，原因是应用在较长一段时间内（超过 10 秒）一直处于不稳定状态。

这通常是因为页面上还有一些待处理的微任务或宏任务。

Angular 水合依赖于 `ApplicationRef.isStable` 在应用变得稳定时发出的信号：

- 在服务端渲染（SSR）期间，用它来启动序列化过程
- 在浏览器中，用这个信号启动水合后的清理工作，移除那些未被认领的 DOM 节点

如果 `ApplicationRef.isStable` 在 10 秒内没有发出 `true`，就会显示这个警告。如果这是有意为之、你的应用会在稍后才稳定下来，可以选择忽略此警告。

## 使用 zone.js 的应用 {#applications-that-use-zone-js}

在使用 zone.js 的应用中，有多种因素可能导致稳定被延迟，包括待处理的 HTTP 请求、定时器（`setInterval`、`setTimeout`），或者某些持续调用 `requestAnimationFrame` 的逻辑。

### 宏任务 {#macrotasks}

宏任务包括 `setInterval`、`setTimeout`、`requestAnimationFrame` 等函数。
如果在应用的初始化阶段或被引导的组件中调用了其中某个函数，就可能推迟应用变得稳定的时间点。

```ts
@Component({
  selector: 'app',
  template: ``,
})
class Simple {
  constructor() {
    setInterval(() => { ... }, 1000)

    // or

    setTimeout(() => { ... }, 10_000)
  }
}
```

如果必须在初始化阶段调用这些函数，在 Angular zone 之外调用它们即可解决问题：

```ts
class Simple {
  constructor() {
    const ngZone = inject(NgZone);

    ngZone.runOutsideAngular(() => {
      setInterval(() => {}, 1000);
    });
  }
}
```

### 第三方库 {#third-party-libraries}

一些第三方库也会产生长时间运行的异步任务，从而推迟应用的稳定。建议按照上面的方式，在 zone 之外调用相关的库代码。

### 在应用变得稳定之后运行代码 {#running-code-after-an-application-becomes-stable}

你可以在应用变得稳定之后，再运行那些会设置异步任务的代码：

```ts
class Simple {
  constructor() {
    const applicationRef = inject(ApplicationRef);

    applicationRef.isStable.pipe( first((isStable) => isStable) ).subscribe(() => {
      // 注意，这里不需要使用 `runOutsideAngular`，因为 `isStable`
      // 为真值时会在 Angular zone 之外发出事件（假值则在
      // Angular zone 之内发出）。
      setTimeout(() => { ... });
    });
  }
}
```

## 无 Zone 应用 {#zoneless-applications}

在无 Zone（zoneless）场景下，稳定可能会因为 `effect` 中的应用代码陷入无限循环（可能是因为副作用函数中使用的信号在不断变化）或待处理的 HTTP 请求而被推迟。

开发者也可以使用 [`PendingTasks`](https://angular.dev/api/core/PendingTasks) 服务来显式地参与标识应用的稳定状态。如果你在应用中使用了上述 API，请确保调用相应函数把任务标记为已完成。
