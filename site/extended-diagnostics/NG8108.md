# `ngSkipHydration` 应该是静态属性 {#ngskiphydration-should-be-a-static-attribute}

`ngSkipHydration` 是一个特殊属性，用于告诉 Angular 某个组件应当退出[水合（Hydration）](/guide/hydration)。
此诊断（Diagnostic）用于确保 `ngSkipHydration` 属性是静态设置的，并且其值为 `"true"` 或为空。

```ts
import {Component} from '@angular/core';

@Component({
  template: `<user-viewer ngSkipHydration="hasUser" />`,
})
class MyComponent {
  hasUser = true;
}
```

## 这有什么问题？ {#what-s-wrong-with-that}

作为由 Angular 实现的特殊属性，`ngSkipHydration` 必须能够被静态分析，这样 Angular 才能在编译期就知道某个组件是否需要水合。

## 应该怎么做？ {#what-should-i-do-instead}

使用 `ngSkipHydration` 时，请确保将其设置为静态属性（也就是说，不要使用 Angular 模板绑定语法）。

```ts
import {Component} from '@angular/core';

@Component({
  template: `
    <user-viewer ngSkipHydration />
    <user-viewer ngSkipHydration="true" />
  `,
})
class MyComponent {}
```

如果需要条件判断，可以把组件包裹在 `*ngIf` 中。

```ts
import {Component} from '@angular/core';

@Component({
  template: `
    <div *ngIf="hasUser; else noUser">
      <user-viewer ngSkipHydration />
    </div>

    <ng-template #noUser>
      <user-viewer />
    </ng-template>
  `,
})
class MyComponent {}
```

## 配置要求 {#configuration-requirements}

必须启用 [`strictTemplates`](/tools/cli/template-typecheck#strict-mode)，扩展诊断（Extended Diagnostics）才会输出。
`skipHydrationNotStatic` 除了 `strictTemplates` 之外没有其他要求。

## 如果无法避免怎么办？ {#what-if-i-can-t-avoid-this}

可以通过编辑项目的 `tsconfig.json` 文件来禁用此诊断：

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "skipHydrationNotStatic": "suppress"
      }
    }
  }
}
```

更多信息，请参阅[扩展诊断配置](/extended-diagnostics#configuration)。
