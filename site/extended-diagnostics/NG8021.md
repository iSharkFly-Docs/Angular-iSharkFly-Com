# 延迟触发器配置错误 {#defer-trigger-misconfiguration}

此诊断（Diagnostic）用于检测 `@defer` 块中不可达或冗余的触发器（trigger）。

```ts
import {Component} from '@angular/core';

@Component({
  template: `
    @defer (on immediate; on timer(500ms)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

## 这有什么问题？ {#what-s-wrong-with-that}

此诊断会识别延迟触发器配置中的几种有问题的模式，这些模式会导致：

- **多余的代码**：永远不会影响行为
- **错失优化机会**：无法获得更好的性能
- **不可达的预取触发器**：永远不会执行

## 会触发诊断警告的情况 {#diagnostic-warning-cases}

此诊断会标记以下有问题的模式：

### `immediate` 与预取触发器同时使用 {#immediate-with-prefetch-triggers}

```ts [prefetch never runs]
@Component({
  template: `
    @defer (on immediate; prefetch on idle) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```ts [remove redundant prefetch]
@Component({
  template: `
    @defer (on immediate) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

### 预取计时器不早于主计时器 {#prefetch-timer-not-earlier-than-main-timer}

```ts [prefetch is later than main]
@Component({
  template: `
    @defer (on timer(100ms); prefetch on timer(3000ms)) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```ts [equal timing provides no benefit]
@Component({
  template: `
    @defer (on timer(500ms); prefetch on timer(500ms)) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```ts [prefetch fires earlier]
@Component({
  template: `
    @defer (on timer(1000ms); prefetch on timer(500ms)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

### 只有预取触发器而没有主触发器 {#prefetch-without-main-triggers}

```ts [unexpected early fetch]
@Component({
  template: `
    @defer (prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

这种配置可能会让人以为预取只会在 `someFlag` 变为 true 时才执行。但由于主触发器仍然默认为 `on idle`，延迟加载的内容可能会更早地在浏览器空闲期间被获取，实际上绕过了预期的条件。

```ts [explicitly define main trigger]
@Component({
  template: `
    @defer (on interaction; prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

### 预取触发器与主触发器完全相同 {#identical-prefetch-and-main-triggers}

```ts [identical viewport trigger]
@Component({
  template: `
    @defer (on viewport; prefetch on viewport) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```ts [identical interaction target]
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn); prefetch on interaction(loadBtn)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

```ts [remove redundant prefetch]
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

```ts [use different targets for prefetch and main]
@Component({
  template: `
    <div #hoverArea>Hover to prefetch</div>
    <button #clickBtn>Click to load</button>
    @defer (on interaction(clickBtn); prefetch on hover(hoverArea)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

## 配置要求 {#configuration-requirements}

必须启用 [`strictTemplates`](/tools/cli/template-typecheck#strict-mode)，扩展诊断（Extended Diagnostics）才会输出。
`deferTriggerMisconfiguration` 除了 `strictTemplates` 之外没有其他要求。

## 如果无法避免怎么办？ {#what-if-i-can-t-avoid-this}

可以通过编辑项目的 `tsconfig.json` 文件来禁用此诊断：

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "deferTriggerMisconfiguration": "suppress"
      }
    }
  }
}
```

更多信息，请参阅[扩展诊断配置](/extended-diagnostics#configuration)。
