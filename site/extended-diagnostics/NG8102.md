# 对不可为空的值使用空值合并 {#nullish-coalescing-not-nullable}

此诊断（Diagnostic）用于检测 Angular 模板（Template）中无用的空值合并（nullish coalescing）运算符（`??`）。
具体来说，它会查找输入值不是「可为空（nullable）」的运算，即其类型不包含 `null` 或 `undefined`。
对于这样的值，`??` 右侧的内容永远不会被用到。

```ts
import {Component} from '@angular/core';

@Component({
  // 模板会显示 `username`（如果存在）；如果它是 `null` 或 `undefined`，
  // 则回退为 'root'。
  template: `<div>{{ username ?? 'root' }}</div>`,
})
class MyComponent {
  // `username` 被声明为 `string`，它_不可能_是 `null` 或
  // `undefined`。
  username: string = 'Angelino';
}
```

## 这有什么问题？ {#what-s-wrong-with-that}

对不可为空的输入使用空值合并运算符不会产生任何效果，这说明值所允许的类型与它在模板中的呈现方式之间存在不一致。
开发者可能会合理地认为空值合并运算符右侧的内容在某些情况下会显示出来，但实际上它永远不会被显示。
这可能会让人对程序的预期输出产生困惑。

## 应该怎么做？ {#what-should-i-do-instead}

让模板与声明的类型保持一致。
仔细检查输入的类型，确认它是否真的应该可为空。

如果输入应该可为空，就在它的类型中加上 `null` 或 `undefined` 来表明这一点。

```ts
import {Component} from '@angular/core';

@Component({
  template: `<div>{{ username ?? 'root' }}</div>`,
})
class MyComponent {
  // 现在 `username` 可为空。如果它被设为 `null`，就会显示
  // 'root'。
  username: string | null = 'Angelino';
}
```

如果输入_不_应该可为空，就删除 `??` 运算符及其右操作数，因为 TypeScript 已经保证该值始终不为空。

```ts
import {Component} from '@angular/core';

@Component({
  // 模板始终显示 `username`，它保证永远不会是 `null`
  // 或 `undefined`。
  template: `<div>{{ username }}</div>`,
})
class MyComponent {
  username: string = 'Angelino';
}
```

## 配置要求 {#configuration-requirements}

必须启用 [`strictTemplates`](/tools/cli/template-typecheck#strict-mode)，扩展诊断（Extended Diagnostics）才会输出。
还必须启用 [`strictNullChecks`](/tools/cli/template-typecheck#strict-null-checks)，才会输出 `nullishCoalescingNotNullable` 诊断。

## 如果无法避免怎么办？ {#what-if-i-can-t-avoid-this}

可以通过编辑项目的 `tsconfig.json` 文件来禁用此诊断：

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "nullishCoalescingNotNullable": "suppress"
      }
    }
  }
}
```

更多信息，请参阅[扩展诊断配置](/extended-diagnostics#configuration)。
