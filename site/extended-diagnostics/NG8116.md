# 缺少结构型指令 {#missing-structural-directive}

此诊断（Diagnostic）用于确保在模板（Template）中使用了自定义结构型指令（例如 `*select` 或 `*featureFlag`）的独立组件（Standalone Component）导入了这些指令所需的依赖。

```ts
import {Component} from '@angular/core';

@Component({
  // 模板中使用了 `*select`，但没有导入对应的指令。
  imports: [],
  template: `<p *select="let data; from: source">{{ data }}</p>`,
})
class MyComponent {}
```

## 这有什么问题？ {#what-s-wrong-with-that}

在未导入的情况下使用结构型指令会在运行时失败，因为 Angular 会尝试绑定到 HTML 元素上的 `select` 属性，而该属性并不存在。

## 应该怎么做？ {#what-should-i-do-instead}

确保将对应的结构型指令导入到组件中：

```ts
import {Component} from '@angular/core';
import {SelectDirective} from 'my-directives';

@Component({
  // 将 `SelectDirective` 添加到 `imports` 数组中，使其可以在模板中使用。
  imports: [SelectDirective],
  template: `<p *select="let data; from: source">{{ data }}</p>`,
})
class MyComponent {}
```

## 配置要求 {#configuration-requirements}

必须启用 [`strictTemplates`](/tools/cli/template-typecheck#strict-mode)，扩展诊断（Extended Diagnostics）才会输出。
`missingStructuralDirective` 除了 `strictTemplates` 之外没有其他要求。

## 如果无法避免怎么办？ {#what-if-i-can-t-avoid-this}

可以通过编辑项目的 `tsconfig.json` 文件来禁用此诊断：

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "missingStructuralDirective": "suppress"
      }
    }
  }
}
```

更多信息，请参阅[扩展诊断配置](/extended-diagnostics#configuration)。
