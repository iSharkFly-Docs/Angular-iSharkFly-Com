# Angular 中的无障碍 {#accessibility-in-angular}

使用 Web 的人群多种多样，其中包括有视觉障碍或运动障碍的人。
有各种各样的辅助技术可以让这些人群更容易地与基于 Web 的软件应用进行交互。
此外，把应用设计得更加无障碍，通常也能改善所有用户的体验。

要深入了解设计无障碍应用时会遇到的问题和相关技巧，请参阅 Google web.dev 上的 [Learn Accessibility](https://web.dev/learn/accessibility/) 课程。

本页讨论如何设计对所有用户（包括依赖辅助技术的用户）都友好的 Angular 应用的最佳实践。

## 无障碍属性 {#accessibility-attributes}

构建无障碍的 Web 体验，常常需要设置 [Accessible Rich Internet Applications \(ARIA\) 属性](https://web.dev/learn/accessibility/aria-html/)，在缺少语义的地方补充语义。
使用[属性绑定](/guide/templates/binding#binding-dynamic-properties-and-attributes)模板语法来控制无障碍相关属性的值。

### ARIA 属性和 DOM 属性 {#aria-attributes-and-properties}

在 Angular 中绑定 ARIA 属性时，可以像使用其他 HTML 属性一样直接使用它们。

```html
<button [aria-label]="myActionLabel">…</button>
```

静态的 ARIA 属性就像普通 HTML 属性一样使用。

```html
<button aria-label="Save document">…</button>
```

::: tip 提示
按照惯例，HTML 属性（attribute）使用小写名称 \(`tabindex`\)，而 DOM 属性（property）使用驼峰式名称 \(`tabIndex`\)。

:::

有些 ARIA 模式暴露的 DOM API 或指令输入接受结构化的值（例如 `Element` 引用的集合）。这种情况下请使用标准的属性绑定（Property Binding），让底层的关联关系保持同步。

```ts
@Component({
  template: `
    <h2 #dialogTitle>Attention</h2>
    <p #dialogDescription>Please review your answers before continuing.</p>

    <section role="dialog" [ariaLabelledByElements]="[dialogTitle, dialogDescription]">
      <ng-content />
    </section>
  `,
})
export class ReviewDialog {}
```

这里的 `[ariaLabelledByElements]` 接受一个元素数组，因此每当模板数据变化时，属性绑定都会让元素引用保持最新。

ARIA 属性语法的概要，请参阅[绑定指南](/guide/templates/binding#aria-attributes)。

## Angular UI 组件 {#angular-ui-components}

由 Angular 团队维护的 [Angular Material](https://material.angular.dev) 库是一套可复用的 UI 组件，其目标是做到完全无障碍。
[组件开发工具包（CDK）](https://material.angular.dev/cdk/categories)中包含 `a11y` 包，提供了支持无障碍各个方面的工具。
例如：

- `LiveAnnouncer` 用于通过 `aria-live` 区域向屏幕阅读器用户播报消息。
  有关 [aria-live 区域](https://www.w3.org/WAI/PF/aria-1.1/states_and_properties#aria-live)的更多信息，请参阅 W3C 文档。

- `cdkTrapFocus` 指令会把 Tab 键的焦点限制在某个元素内。
  可以用它为模态对话框这类需要限制焦点的组件打造无障碍的体验。

这些工具以及其他工具的完整说明，请参阅 [Angular CDK 无障碍概述](https://material.angular.dev/cdk/a11y/overview)。

对于需要可复用的 WAI-ARIA 交互模式、并且使用自定义样式的组件，[Angular Aria](/guide/aria/overview) 为手风琴、组合框、列表框、菜单、标签页和工具栏等模式提供了无头（headless）指令。
这些指令负责处理键盘交互、ARIA 属性、焦点管理和屏幕阅读器支持，同时让你自己为应用提供 HTML 结构和样式。

### 增强原生元素 {#augmenting-native-elements}

原生 HTML 元素本身就包含了若干对无障碍很重要的标准交互模式。
编写 Angular 组件时，应该尽可能直接复用这些原生元素，而不是重新实现那些已经得到良好支持的行为。

例如，与其为一种新样式的按钮创建一个自定义元素，不如创建一个使用属性选择器、作用于原生 `<button>` 元素的组件。
这种做法最常用于 `<button>` 和 `<a>`，但也适用于许多其他类型的元素。

你可以在 Angular Material 中看到这种模式的示例：
[`MatButton`](https://github.com/angular/components/blob/main/src/material/button/button.ts#L33C3-L36C5)、[`MatTabNav`](https://github.com/angular/components/blob/main/src/material/tabs/tab-nav-bar/tab-nav-bar.ts#L62) 和 [`MatTable`](https://github.com/angular/components/blob/main/src/material/table/table.ts#L40)。

### 为原生元素使用容器 {#using-containers-for-native-elements}

有时，使用合适的原生元素需要一个容器元素。
例如，原生的 `<input>` 元素不能有子元素，所以任何自定义的文本输入组件都需要用额外的元素包裹 `<input>`。
如果只是把 `<input>` 放在自定义组件的模板中，组件的使用者就无法给这个 `<input>` 元素设置任意的属性。
正确的做法是创建一个容器组件，通过内容投影把原生控件纳入组件的 API。

[`MatFormField`](https://material.angular.dev/components/form-field/overview) 就是这种模式的一个例子。

## 案例研究：构建自定义进度条 {#case-study-building-a-custom-progress-bar}

下面的示例展示了如何使用宿主绑定（Host Binding）控制无障碍相关属性，让进度条变得无障碍。

- 组件定义了一个支持无障碍的元素，同时带有标准 HTML 属性 `role` 和 ARIA 属性。
  ARIA 属性 `aria-valuenow` 绑定到用户的输入。
- 在模板中，`aria-label` 属性确保屏幕阅读器可以访问该控件。

::: code-group

```ts [progress-bar.component.ts]
/* eslint-disable @angular-eslint/no-host-metadata-property */
import {Component, input} from '@angular/core';

/**
 * 进度条组件示例。
 */
@Component({
  selector: 'app-example-progressbar',
  template: '<div class="bar" [style.width.%]="value()"></div>',
  styleUrls: ['./progress-bar.component.css'],
  host: {
    // 把该组件的 role 设为 "progressbar"
    role: 'progressbar',

    // 设置 progressbar 角色的最小值和最大值。
    'aria-valuemin': '0',
    'aria-valuemax': '100',

    // 更新进度条当前值的绑定。
    '[attr.aria-valuenow]': 'value()',
  },
})
export class ExampleProgressbarComponent {
  /** 进度条的当前值。 */
  value = input(0);
}
```

```html [app.component.html]
<h1>Accessibility Example</h1>
<label for="progress-value">
  Enter an example progress value
  <input
    id="progress-value"
    type="number"
    min="0"
    max="100"
    [value]="progress"
    (input)="setProgress($event)"
  />
</label>

<!-- 进度条的使用者设置 aria-label，用来说明这个进度代表什么。 -->
<app-example-progressbar [value]="progress" aria-label="Example of a progress bar" />
```

:::

## 路由 {#routing}

### 导航后的焦点管理 {#focus-management-after-navigation}

跟踪和控制 UI 中的[焦点](https://web.dev/learn/accessibility/focus/)，是无障碍设计中一项重要的考量。
使用 Angular 路由时，你应该决定导航之后页面焦点落在哪里。

为了不只依赖视觉提示，你需要确保路由代码在页面导航之后更新焦点。
使用 `Router` 服务的 `NavigationEnd` 事件来判断何时更新焦点。

下面的示例展示了如何在导航之后找到 DOM 中的主要内容标题并让它获得焦点。

```ts
router.events.pipe(filter((e) => e instanceof NavigationEnd)).subscribe(() => {
  const mainHeader = document.querySelector('#main-content-header');
  if (mainHeader) {
    mainHeader.focus();
  }
});
```

在真实的应用中，获得焦点的元素取决于你的应用的具体结构和布局。
获得焦点的元素应该让用户能够立即进入刚刚通过路由显示出来的主要内容。
你应该避免在路由变化后焦点回到 `body` 元素的情况。

### 标识当前激活的链接 {#active-links-identification}

应用在激活的 `RouterLink` 元素上的 CSS 类（例如通过 `RouterLinkActive`）可以提供视觉提示，帮助识别当前激活的链接。
遗憾的是，视觉提示对盲人或视力障碍用户没有帮助。
给元素加上 `aria-current` 属性，可以帮助识别当前激活的链接。
更多信息请参阅 [Mozilla Developer Network \(MDN\) aria-current](https://developer.mozilla.org/docs/Web/Accessibility/ARIA/Attributes/aria-current))。

`RouterLinkActive` 指令提供了 `ariaCurrentWhenActive` 输入，当链接变为激活状态时，会把 `aria-current` 设为指定的值。

下面的示例展示了如何给激活的链接应用 `active-page` 类，并在它们激活时把 `aria-current` 属性设为 `"page"`：

```html
<nav>
  <a routerLink="home" routerLinkActive="active-page" ariaCurrentWhenActive="page"> Home </a>
  <a routerLink="about" routerLinkActive="active-page" ariaCurrentWhenActive="page"> About </a>
  <a routerLink="shop" routerLinkActive="active-page" ariaCurrentWhenActive="page"> Shop </a>
</nav>
```

## 延迟加载 {#deferred-loading}

使用 Angular 的 `@defer` 块延迟加载内容时，要考虑对使用辅助技术的用户在无障碍方面的影响。
当延迟加载的组件加载完成时，屏幕阅读器可能不会自动播报内容的变化，用户可能因此察觉不到新内容。

为了确保延迟加载的内容变化能被正确播报，请用带有合适 ARIA live 区域的元素包裹 `@defer` 块。
详细的指导和示例请参阅 [defer 指南中的无障碍部分](/guide/templates/defer#keep-accessibility-in-mind)。
